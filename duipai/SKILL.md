# 对拍(stress testing)

孩子的代码过了样例但提交失败,通常不是"运气差",而是样例太弱,盖不住边界和随机情况。对拍的原理:写一个**显然正确但很慢的暴力解**当裁判,用**数据生成器**批量造小数据,让两份代码同题竞答,输出不一致就抓到了反例。

这个 skill 有双重目标:①帮孩子当下找到 bug;②让孩子学会赛场上独立完成对拍——对拍是 NOIP/CSP 赛场标准技能,不是平时才有的外挂。所以**每次产出都要带教学成分**,不能只甩结果。

## 教学阶梯(四级)

目标是让孩子最终在赛场上 15 分钟内独立搭起一套对拍。按级递进,用户说"L2"/"让他写暴力"等即切换,未说明时沿用上次级别,首次默认 L1:

- **L1 看范例**:skill 代写全套,暴力附「讲解卡」(见下)。要求孩子读完讲解卡后给家长复述"这个暴力为什么显然正确、赛场上怎么想到"——衔接费曼法。
- **L2 孩子写暴力**:skill 写生成器并跑对拍。暴力最先练,因为它同时是赛场保底的部分分。skill 审查孩子的暴力是否"显然正确"(必要时用另一种写法的暴力反拍它),有问题给引导提示,不直接改。
- **L3 孩子写暴力 + 生成器**:skill 只审查(生成器重点看边界覆盖和结构化数据的造法,如随机树、合法区间)并跑对拍。
- **L4 训练模式(赛前)**:全套自己来,包括对拍脚本(能默写 `references/contest-templates.md` 里的模板)。skill 只当裁判,计时,目标 15 分钟内搭完。

以提高组水平,每级停留一两周、每周两题即可推进;卡住就退回上一级多看两个范例。

## 工作流程

### 1. 收集信息

需要:题目(原文或链接)、孩子的代码、**数据范围**。数据范围缺失时必须先问或查——生成器和暴力的复杂度上限都依赖它。确认评测方式:唯一答案(直接比对)还是多解(需要写 checker)。

### 2. 静态预判(不超过两分钟)

对拍之前先快速过一遍代码,对照"样例过、提交挂"的五大常见原因:边界(n=0/1、全相同、极值)、多测未清空、int 溢出、数组开小/越界、读入输出格式。发现疑点不要直接说破——记下来,在写生成器时**定向造一组能触发它的数据**,让反例自己说话,这比口头指出记得牢。

### 3. 写暴力解

原则:**宁可 O(n!) 也要显然正确**,每行代码都能指着题面读出来,不做任何优化。暴力必须附「讲解卡」,固定三行:

- 用的哪一板斧:①直译模拟 ②全枚举(排列/子集/区间)③无脑 DFS
- 为什么显然正确(一句话)
- 复杂度与适用规模(如"O(n³),n≤50 内随便跑")

### 4. 写数据生成器

- **小数据优先**:默认 n≤8、值域 ≤20。小数据照样能拍出绝大多数逻辑错误,而且反例小到孩子能手算复查——这是教学价值的关键。
- **边界特化组**:除了纯随机,必须定向覆盖:最小规模(n=1)、全相同值、极值(数据范围上限,验溢出)、退化结构(树退化成链、区间全部重叠等,视题目而定)。
- 生成器从命令行接收种子和规模参数,保证可复现、可调档。

### 5. 跑对拍

用 `scripts/duipai.py`(通用 runner,支持 .cpp/.py 的生成器与解法、自定义 checker、TLE 检测):

```bash
python3 <skill目录>/scripts/duipai.py --gen gen.cpp --brute brute.cpp --sol sol.cpp --rounds 300
```

小规模拍不出时依次升级:调大规模和值域 → 上边界特化组 → 用满档数据测 TLE(慢也是"提交挂"的常见原因)→ 若仍拍不出,提醒检查读入输出格式与题意理解偏差(这两类对拍抓不到)。

每题的产物统一放当前目录下 `对拍/<题目名>/`(gen、brute、脚本输出的反例文件都在里面),方便孩子复盘。

### 6. 报告(教学导向)

找到反例后,报告固定包含:最小反例数据、两边输出对比、错误类型归类(边界/溢出/清空/逻辑/TLE)。**默认不直接修改孩子的代码**——给一条引导提示,例如"用这组 n=1 的数据在纸上走一遍你的循环,第几步和暴力分岔了?"。用户明确说"直接修"才动手改。

### 7. 赛场迁移(每次产出末尾必带)

附一小节「这套东西赛场上怎么复现」,指向 `references/contest-templates.md`:暴力三板斧详解、可默写的 Windows bat / Linux bash 对拍模板、C++ 生成器模板、什么情况下值得花 15 分钟对拍的决策清单。平时每次看到这一节,赛前切训练模式实操,技能才真正长在孩子身上。
